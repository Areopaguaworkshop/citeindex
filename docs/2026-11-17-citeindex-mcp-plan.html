Feasibility & Architecture Plan

CiteIndex — MCP Server Plan

Expose ingestion, library lookup, and citation verification as MCP tools for OpenCode, Pi, OMP, and Codex
Verdict: feasible without rewriting the pipeline. All four harnesses installed on this machine support local (stdio) and remote (Streamable HTTP) MCP servers. CiteIndex already exposes a Python API (citeindex.ingest() plus the corpus artifacts), so the work is a thin, permissioned MCP adapter — not a second ingestion engine.
Implemented MVP (2026-11-17): citeindex-mcp now ships phases 0–2 — library_list/search/get, citation_verify, citation_format, ingest_url (write-gated, deterministic by default), citeindex_info, corpus/skill resources, and cite-this-source / ingest-verified prompts. The project's citation-verification skill is served as citeindex://skills/citation-verification and embedded in both prompts. Verified with stdio and Streamable HTTP round trips, a live PLOS URL ingest (~3.5 s, deterministic metadata), and 7 dedicated MCP tests; wheel builds include the skill under citeindex/mcp/skills/.

B

Why MCP Instead of Shelling Out

  • Typed calls: agents pass structured arguments; no quoting, escaping, or parsing CLI output.
  • Structured results: CSL JSON, field status, evidence, artifact paths — not stdout prose.
  • Resources: agents can read citeindex://library/<id>/csl directly instead of re-running ingestion.
  • Prompts: ship the "cite → verify → report" workflow as an MCP prompt instead of repeating instructions per harness.
  • Governance: per-tool annotations and client approval prompts distinguish read-only lookup from corpus writes.
MCP does not remove the cost or permissions of ingestion: OCR, media, and network fetches still take the same time and still need the same sandbox/network access. It only makes the interface safer and more direct.

Architecture

Agent (OpenCode / Codex / Pi / OMP)
        │  MCP (stdio default, optional Streamable HTTP)
        ▼
citeindex-mcp                         ← new console script
        │
        ├── tools_library.py          read-only corpus/library index
        ├── tools_ingest.py           wraps citeindex.ingest()
        ├── jobs.py                   bounded worker + progress + cancel
        └── security.py               roots allowlist, write gate, audit log
        │
        ▼
citeindex.ingest() / pipelines / corpus artifacts
(csl.json, merkle.json, citation_verification.json, source.html, library/*.md)
  • Packaging: extra mcp = ["mcp>=2.3,<3"] and script citeindex-mcp = "citeindex.mcp.server:main".
  • SDK: implement against the MCP Python SDK v2 MCPServer (from mcp.server.mcpserver import MCPServer).
  • Transport: stdio by default; citeindex-mcp --http 127.0.0.1:8765 serves Streamable HTTP for containers or shared use.
  • State: corpus root resolved once at startup; a per-corpus writer lock prevents concurrent ingestion collisions.

MVP intentionally stays at 6–8 tools so the tool list remains legible to smaller models. Bulk data is served through resources, not extra tools.

E

Resources & Prompts

  • citeindex://library/{source_id}/csl — processor-ready CSL JSON plus _field_status and _field_evidence.
  • citeindex://corpus/{source_id}/manifest — Merkle manifest and artifact index.
  • citeindex://corpus/{source_id}/verification — latest citation_verification.json, when present.
  • citeindex://skills/{name} — serves the project's canonical .agents/skills/<name>/SKILL.md (or CITEINDEX_SKILL_ROOT); wheel builds force-include it under citeindex/mcp/skills/ so installed servers keep the skill.
  • Prompt cite-this-source — ingest (or load) → verify → report only source-supported fields, with evidence quotes.
  • Prompt repair-citation — generate a repair proposal; applying it stays a separate, explicitly approved tool call (phase 4).
Shipping the verification prompt inside the server keeps behaviour consistent across harnesses and matches AGENTS.md: never present citation accuracy before the evidence audit.

Client Wiring

OpenCode — CLI or opencode.json:

opencode mcp add citeindex -- citeindex-mcp --corpus-root /home/ajiap/Projects/citeindex/corpus

// ~/.config/opencode/opencode.json
"mcp": { "servers": { "citeindex": {
  "type": "local", "enabled": true,
  "command": ["citeindex-mcp", "--corpus-root", "/path/to/corpus"]
}}}

Codex — CLI or ~/.codex/config.toml:

codex mcp add citeindex -- citeindex-mcp --corpus-root /path/to/corpus

[mcp_servers.citeindex]
command = "citeindex-mcp"
args = ["--corpus-root", "/path/to/corpus"]

Pi — CLI or ~/.pi/agent/mcp.json:

pi mcp add citeindex -- citeindex-mcp --corpus-root /path/to/corpus

{ "mcpServers": { "citeindex": {
  "command": "citeindex-mcp",
  "args": ["--corpus-root", "/path/to/corpus"]
}}}

OMP — edit ~/.omp/agent/mcp.json (same schema as Pi; this build has no omp mcp add):

{ "mcpServers": { "citeindex": {
  "command": "citeindex-mcp",
  "args": ["--corpus-root", "/path/to/corpus"]
}}}

Shared HTTP server — one process, all harnesses:

citeindex-mcp --http 127.0.0.1:8765 --corpus-root /path/to/corpus

# Codex:   codex mcp add citeindex --url http://127.0.0.1:8765/mcp
# OpenCode: opencode mcp add citeindex --url http://127.0.0.1:8765/mcp
# Pi:      pi mcp add citeindex --url http://127.0.0.1:8765/mcp
# OMP:     { "mcpServers": { "citeindex": { "url": "http://127.0.0.1:8765/mcp" } } }

Do not expose a write-enabled HTTP server on a public interface; bind to loopback and use auth if it ever leaves the machine.

Risks & Mitigations

RiskMitigation
MCP SDK churn (v1 FastMCP → v2 MCPServer)Pin mcp>=2.3,<3; keep SDK imports in one adapter module; CI smoke test against the pinned version.
Long ingestion exceeds agent/tool timeoutsURL ingest capped (~60 s); file/media ingestion always returns a job_id; progress notifications + cancel.
Client sandbox/network differencesstdio local mode is the default; document per-client env; provide HTTP mode for containerised clients.
Tool list crowds the model contextSix to eight tools maximum in MVP; resources carry bulk data; defer repair/apply tools.
Concurrent ingestion corrupts a corpusPer-corpus writer lock; queue submissions; idempotent re-ingestion via existing artifact replacement.
Optional OCR/media dependencies missingCapability detection in citeindex_info; return an actionable error instead of silently degrading.
Path traversal or SSRF through tool argumentsRoot allowlist + validate_public_url; reject absolute paths outside roots; audit rejected calls.
OMP has no mcp add commandDocument the manual ~/.omp/agent/mcp.json entry; verify with a session-level tool listing.
J

Recommendation & Success Criteria

MVP delivered; proceed to file ingestion. Phases 0–2 are implemented and tested. Phase 3 (job manager + ingest_file) should be built only after write approval behaviour is proven in real sessions; the URL path already exercises the same permission and evidence rules.
  1. An agent can say "cite this URL" and receive CSL JSON with _field_status and evidence quotes — no shell commands.
  2. An agent can search the existing corpus and format an existing record without re-ingesting.
  3. Write-enabled mode is explicit, bounded to an allowlisted corpus, and leaves an audit trail.
  4. All four harnesses load the same tool set and return identical results for the same inputs.

Implementation: citeindex/mcp/ with protocol tests in tests/test_mcp_server.py, using the same evidence rules as the CLI.

The citeindex PyPI name is already registered (0.14.0). Publish 0.15.x under that project; do not create a second package just for MCP. uvx --from 'citeindex[mcp]' citeindex-mcp gives the same one-command ergonomics without splitting versions.

Release checklist: bump version → uv lock → uv build → verify the wheel contains citeindex/mcp/* and the bundled skill → test base install (helpful extra message) and citeindex[mcp] install → stdio + HTTP smoke → publish → tag.
